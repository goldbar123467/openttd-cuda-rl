# ADR 0003: Select the `road_freight_v1` deterministic fixture

- Status: accepted for PORT002A; PORT002B open
- Decision date: 2026-07-30
- Source basis: OpenTTD commit `29f808ef0022064e6d9a83c8476d1e0f4686af86`
- Contract artifact: `oracle/fixtures/road_freight_v1/fixture.manifest.json`

## Context and closure boundary

P0 needs one deliberately narrow world that exercises construction, vehicle
creation, two orders, movement, industry production, station capture, loading,
accepted delivery, and payment. Breadth is harmful here: every unrelated map
feature or gameplay system expands the state projection and makes the first
divergence harder to diagnose.

This ADR was intentionally recorded before `fixture.sav` was created. It freezes
all choices that can be proven from the pinned source and marks observations
that can only come from the generated bytes or PORT003 instrumentation as
blocking evidence. No unresolved timer, RNG word, command cost, or milestone
tick is guessed. The committed manifest is a PORT002A-frozen artifact with
explicit PORT002B blockers, not an overall PORT002 pass artifact.

Two independent, settings-aligned pinned-worktree runs emitted identical
10008-byte final saves with SHA-256
`74c9be53902598061e1e82835c394a37b77bfc71c818de1df8456cdfc2804d20`.
They also produced equal canonical map-plane streams and a verified creation
executable identity, closing PORT002A. PORT002B closes later, after PORT003
proves equal initial projections from two isolated loads and a native replay
reaches the declared milestones.

## Decision

### World, time, and terrain

- Climate: temperate (`LandscapeType::Temperate`, setting value `0`).
- Start date: 1950-01-01.
- Dimensions: exactly 64×64. OpenTTD stores both map dimension settings as
  exponent `6`.
- Map source: native `GWM_EMPTY`, which the pinned source defines as an empty
  sea-level map. The generation seed is `0x52465631` (`1380341297`). The
  generator version is the pinned commit.
- Wall-clock time was not frozen with `faketime` or `LD_PRELOAD`, and is not an
  authoritative input. OpenTTD's process startup may initially seed from real
  time, but fixture generation resets the persisted gameplay seed and the
  builder explicitly fixes the interactive RNG and savegame ID. Independent
  release runs at different real times produced byte-identical save and map
  planes, which is the retained nondependence evidence.
- The builder explicitly sets the interactive RNG seed to `0x49524631`
  (`1230128689`) before saving and fixes the savegame ID to
  `50304649585455524553415645494431`. These creation inputs do not replace the
  required post-load RNG observation.
- Both creation logs record the same pre-save boundary: tick `0`, calendar and
  economy date `712223`, both fractional counters `0`, state RNG words
  `0x5b969220:0x7657b27e`, and interactive RNG words
  `0x49524631:0x49524631`. These measured creation values are frozen separately
  from PORT002B's required after-load equality proof.
- Final map planes: both runs emitted the canonical tile-index-order stream
  `type,height,m1,m2le,m3,m4,m5,m6,m7,m8le`, 12 bytes for each of 4096 tiles.
  Both 49152-byte streams equal SHA-256
  `5a933bc43d59c05b0d8fda519aec0aafa71b16d50a03aea83aefade7a57c9dd6`.

An original industry needs a town association. The disposable builder uses the
native `FoundTown` command at `(32,16)` (`TileIndex 1056`) with the fixed,
non-personal name `P0 Fixture Town`, then uses native clearing commands to
remove every generated house and road while retaining `TownID 0`. The frozen
town has population 0, house count 0, road-tile count 0, its growing flag
cleared, and `TOWN_GROWTH_RATE_NONE`. This construction history is part of the
creation log, not replay.

### Company

- Exactly one human company: `CompanyID 0`.
- No AI company and `difficulty.max_no_competitors = 0`.
- Company name policy: source-generated default company/president names only.
  The separately declared fixed town string is generic and non-personal; no
  custom company, president, station, vehicle, or sign string enters the
  fixture.
- Opening balance: `10000000`; current loan: `0`. The disposable builder first
  creates native `CompanyID 0`, then performs this declared creation-only
  balance operation before saving. It is not a cheat flag and no balance-set
  operation exists in the replay command schema.
- Cheats and infinite money: disabled. No direct balance mutation remains
  reachable during replay.

The exact sum of the ten native command costs must be observed during fixture
qualification. The required funding invariant is:

`opening_balance >= command_cost_total + 2500000`.

The `2500000` reserve is a 25% opening-balance safety margin. Until native command
test/execute results supply `command_cost_total`, funding is not proven and
PORT002A cannot pass.

### Producer, acceptor, and cargo

The selected pair is the preferred temperate coal route:

| Role | Pool ID | Original type | Layout | Anchor | Exact occupied tiles |
|---|---:|---|---:|---|---|
| Producer | 0 | Coal Mine (`IndustryType 0`) | runtime selected-layout raw value 2 | `(8,27)` / `TileIndex 1736` | all nine tiles in the 3×3 rectangle `(8..10,27..29)`; indices `1736,1737,1738,1800,1801,1802,1864,1865,1866` |
| Acceptor | 1 | Power Station (`IndustryType 1`) | runtime selected-layout raw value 2 | `(49,27)` / `TileIndex 1777` | occupied indices `1778,1779,1841,1842,1843,1905,1906,1907`; 3×3 bounds with anchor index `1777` unoccupied |

Cargo is original coal: global cargo ID `1`, label `COAL`, class `Bulk` plus
`NonPotable`. The coal mine specification produces coal at original rate `15`.
The builder reports raw `selected_layout=2` for both industries. The contract
does not infer an alternate index convention from that runtime value. Both industry
location bounds are exactly 3×3; the manifest separately records occupied
industry tiles so the unoccupied power-station anchor corner is not invented as
an industry tile. The power-station industry accepts coal at multiplier `256`; its accepting tile
has eight acceptance units. These facts are source-backed in
`src/table/build_industry.h` and `src/table/cargo_const.h`.

This pair is selected because it has one produced cargo, one terminal acceptor,
no processing output, no refit, and no passenger/town-growth dependency. The
economy type is `Frozen`, which the pinned enum defines as stopping production
changes and industry closures. Industry cargo scale remains the source default
`100` so the native production cadence is preserved rather than invented.

### Vehicle availability

- Global `EngineID 123`, road-engine-local ID `7`.
- Original name: Balogh Coal Truck.
- Native cargo: coal.
- Capacity: 20 tons.
- Climate mask: temperate and arctic; temperate is therefore supported.
- Introduction offset: 5479 days after 1920-01-01 (1935), so it is introduced
  before the 1950 start boundary.
- Base availability life: 55 years; the 1950 boundary lies inside it.
- Articulated: false under the original one-part road-vehicle table.
- `vehicle.never_expire_vehicles` remains false. Availability is proven by the
  native rules rather than bypassed.

### Coordinates and catchment

The road is a single flat horizontal `ROADTYPE_ROAD` line at `y=31`, covering
every tile from `x=10` through `x=52`. It is deliberately expressed as three
native long-road commands so the two junction boundaries are explicit:

1. west segment `(10,31)` through `(12,31)`;
2. middle segment `(12,31)` through `(48,31)`;
3. east segment `(48,31)` through `(52,31)`.

The pickup truck bay is at `(12,30)` with `DiagDirection::SE` raw `uint8_t=1`
and accesses road tile `(12,31)`. The delivery truck bay is at `(48,30)` with
the same source symbol/raw value and accesses `(48,31)`. Both are one-by-one,
non-drive-through truck bays. The road depot is at `(9,31)` with
`DiagDirection::SW` raw `uint8_t=2` and accesses `(10,31)`.
The initial spawn path is `(9,31)`, `(10,31)`, `(11,31)`, `(12,31)`.

These are source enum names and serialized command argument values, not compass
labels inferred from prose. In the pinned `_tileoffs_by_diagdir` table,
`DiagDirection::SE` is `{0,+1}` and `DiagDirection::SW` is `{+1,0}`. The
validator checks those offsets against each declared access tile.

`station.modified_catchment` is false, selecting `CA_UNMODIFIED = 4` in the
pinned source. The pickup stop is within four tiles of the coal-mine layout;
the delivery stop is within four tiles of the power-station layout. The strict
validator recomputes both proofs and rejects either stop when moved outside its
industry catchment.

Every declared coordinate satisfies `0 <= x < 64` and `0 <= y < 64`. The
validator expands every road segment, checks four-neighbour connectivity, and
requires each stop and depot to be adjacent to its declared road access.

### Replay command boundary and order sequence

Replay starts after a successful isolated fixture load and before the first
simulation tick or scripted command. All ten actions enter through the pinned
native command dispatcher in this exact order:

1. `Commands::BuildRoadLong` — west segment;
2. `Commands::BuildRoadLong` — middle segment;
3. `Commands::BuildRoadLong` — east segment;
4. `Commands::BuildRoadDepot` — depot direction `DiagDirection::SW`, raw `2`;
5. `Commands::BuildRoadStop` — pickup bay direction `DiagDirection::SE`, raw
   `1`, non-drive-through;
6. `Commands::BuildRoadStop` — delivery bay direction `DiagDirection::SE`, raw
   `1`, non-drive-through;
7. `Commands::BuildVehicle` — global `EngineID 123` in the depot;
8. `Commands::InsertOrder` — pickup at order position 0, full-load-any;
9. `Commands::InsertOrder` — delivery at order position 1,
   unload-if-accepted;
10. `Commands::StartStopVehicle` — start the returned vehicle ID.

The PORT003 command schema will freeze raw typed payload bytes, command-test
results, execute results, returned station/vehicle IDs, and exact costs. This
ADR freezes the gameplay intent, dispatcher, object references, coordinates,
and ordering; it does not pretend unimplemented payload encoding is evidence.

### Initial timer and RNG boundary

The required exact initial record is:

- global simulation tick;
- calendar date and economy date counters;
- calendar and economy timer counters;
- both 32-bit state RNG words;
- both 32-bit interactive RNG words.

Those values are serialized/loaded state observations, not values safely
deducible from the generation seed. They are therefore recorded as
`pending-port003-projection` until PORT003 reads them immediately after load and
before command 1. PORT002B additionally requires a second isolated load with
byte-equal values. This explicit blocked state is the exact decision: no
unmeasured numeric value is accepted.

### Frozen settings and content

`settings.normalized.json` is the complete first-fixture setting profile. It
uses stable internal identifiers, explicit scalar/enum values, pinned-source
anchors, and a behavior/non-authoritative classification. It includes map,
climate, date, frozen economy, inflation, industry production scale, manual
cargo distribution, vehicle availability and breakdowns, acceleration,
servicing, catchment, construction legality, construction/vehicle costs,
road-vehicle queueing and every reached YAPF road penalty, loan/interest,
disasters, competitors, town growth, maintenance, LinkGraph scheduling and
cargo-class distribution, autosave, pause behavior, timekeeping, AI multiplayer
behavior, and load cadence.

The LinkGraph table expresses recalculation defaults as 8 and 32 days. The
fixture is created from an empty isolated configuration, so the pinned
configuration compatibility path at `src/settings.cpp:1427-1429` converts
those values to runtime seconds using `CalendarTime::SECONDS_PER_DAY == 2`.
The frozen runtime values are therefore 16 and 64. A native post-load console
probe confirmed both values from the committed save; the setting identity
records runtime state rather than merely copying table defaults.

The authoritative settings identity excludes only three source-proven client
controls: autosave interval, autosave-on-exit, and pause-on-newgame. All three
remain frozen for isolated replay, and a user configuration override of any is
a preflight failure. Locale, timezone, comments, GUI layout, recent-file
history, and user paths are not exporter inputs.

Content is exactly the committed `opengfx-8.0` baseline profile, including
installed tar SHA-256
`9389bcb0807058c80bd95121e978f05d9ef86b4b1bc3ac2da8da8bb02456043c`.
The NewGRF list and AI-script list are empty, GameScript is null, networking is
false, and authoritative replay requires no network access.

### Excluded branches

The entire road and spawn plan is flat, dry, and unobstructed. It contains no
bridge, tunnel, rail crossing, water crossing, one-way road, tram, articulated
vehicle, or slope. It also excludes aircraft, ships, rail vehicles, disasters,
networking, GameScript, NewGRF callbacks, automatic servicing, inflation,
industry closure/production changes, and town growth.

Each exclusion removes state and source paths without weakening the selected
loop. A single straight route still exercises native construction commands,
pool allocation, road path movement, station catchment, cargo generation and
capture, loading cadence, orders, acceptance, and company payment.

## Evidence and remaining status change

PORT002A is frozen. The canonical settings and items 1–4 below are bound by
`fixture.manifest.json`. Items 5–10 are the remaining PORT002B/native-replay
closure evidence:

1. pinned creation executable SHA-256 and build identity;
2. isolated builder command and native creation-operation log;
3. immutable `fixture.sav` size and SHA-256;
4. final map-plane digest and inspection proving exact objects/tiles;
   the same inspection must prove every normalized setting was applied and
   persisted in the save;
5. exact initial tick, dates, timer counters, and four RNG words;
6. native test/execute result and cost for each of the ten replay commands;
7. funding sum and at least `2500000` remaining safety margin;
8. first cargo capture, loading, accepted delivery, and payment ticks plus exact
   payment ledger event;
9. second isolated load/replay equality evidence;
10. isolated-home audit proving no undeclared config or content was read.

The PORT002A manifest keeps items 5–10 as explicit blockers. Until all ten
items exist, PORT002B and the overall PORT002 gate are open; no PORT002A fact
may be silently changed to satisfy replay.

## Consequences

The fixture is intentionally not representative of general OpenTTD gameplay.
It proves only the frozen road-freight path. Any later expansion—another cargo,
climate, vehicle, infrastructure type, non-flat road, refit, transfer order,
competitor, NewGRF, or network mode—requires a separate versioned fixture and a
field/source-closure review rather than mutation of `road_freight_v1`.
